# 应用内 AI 助手

> 2026-11-01 起。第一、二阶段已完成；第三阶段暂不做，第四阶段待定。

## 目标

AI 助手内建在应用里：一个对话窗口，用户可以问笔记里的内容、让它整理笔记、帮自己学习。MCP（`folio-mcp`）是给外部 AI 工具用的，继续保留，但不是重点。

## 已定的选择

| 问题 | 决定 | 原因 |
|---|---|---|
| 模型 | 用户自己填 key，可以加多家服务商。默认 Claude（`claude-opus-5-5`），也支持 OpenAI 兼容接口（OpenAI、DeepSeek、通义千问、Kimi、Ollama、自定义） | 用户的选择；全球产品，各地能用的模型不同 |
| 修改笔记 | 设置里可选“每次先问我”（默认）或“直接修改”，类似 Claude Code / Codex | 用户的选择 |
| 对话记录 | 跟笔记一样同步 | 用户想在不同设备上接着之前的对话学习 |
| 设置同步 | 模型列表、思考程度、修改模式随笔记同步；当前用哪个模型是每台设备自己的 | 用户希望各端不用重复配置（2026-11-01） |
| API key | 本机存在系统钥匙串里（Android 用 Keystore 加密，都不可用时存在资料库里）；开了同步时，加密后同步到其他设备；页面读不到明文 | 用户选择 key 也同步；数据安全（ARCHITECTURE §5.6） |
| 请求从哪里发 | 由 Rust 发（`crates/folio-ai`），不由网页发 | key 不进入页面；绕开浏览器跨域限制 |

## 结构

```
ChatPanel (web/src/ai/ChatPanel.tsx)
   │ send()                     ai/chat.ts：多轮循环，最多 16 轮
   ▼
backend.aiTurn ──Tauri Channel 流式事件──▶ src-tauri/src/ai.rs ──▶ folio-ai（Anthropic / OpenAI 兼容）
backend.aiTool ─────────────────────────▶ folio_mcp::tools::call（只读工具，和 MCP 用同一套）
```

- **循环在前端。** 每一轮：Rust 调一次模型，把文字和工具调用以事件的形式流式发回；前端并行执行工具，把结果作为下一条消息发回，直到模型说完。每条消息完成时就写进对话文档，所以中途停下也会保留已有的部分。
- **Anthropic：**
  - 流式、`max_tokens` 64000、自适应思考（不传 thinking 参数）、top-level `cache_control`；
  - 工具设 `eager_input_streaming`，前端校验工具输入，不合法时回 `INVALID_JSON` 错误；
  - 检查 `max_tokens` 和 `refusal` 两种停止原因；
  - 模型返回的原始内容（含思考块）原样保存、原样发回；
  - 在 api.anthropic.com 上开启服务端回退（`server-side-fallback-2026-07-01`，`fallbacks: "default"`）。
- **OpenAI 兼容：** `chat/completions` 流式，`tool_calls` 按 index 拼接。
- **服务商和模型分两层**（参照 Raycast）：一家服务商只填一次地址和 key，可以添加多家（设置里的「添加服务商」，或模型菜单里的「添加或管理服务商」）。
  - 模型列表来自服务商自己：`GET {base}/models`（`folio_ai::list_models`，宿主命令 `ai_models`），两种协议和 Ollama 都返回 `{"data": [{"id"}]}`。填好 key 停下约一秒就自动测试并获取。
  - 每台设备把列表缓存在本机设置 `ai.models`，超过 6 小时就在后台重新获取（启动时、打开模型菜单时；打开设置页时强制获取），服务商出了新模型会自动出现。拿不到时沿用上一次的列表。语音、图片、embedding 之类的模型不列出来。
  - 服务商列表里没有的模型可以手动输入 ID，存在同步的 `models` 字段里；以前勾选过的模型也在这里。
  - 输入框的模型菜单按服务商分组，模型多时可以搜索。每台设备记住自己选的服务商和模型（镜像里的 `current` 和 `model`），`ai_turn` 带上这个模型。
- **修改模式在输入框里切换**（参照 Claude 的权限模式）：「先问我」或「直接改」，随设置同步。设置页不再有这一项。
- **对话窗口**（参照 Notion、Obsidian Copilot、ChatGPT）：
  - 输入 `@` 弹出卡片列表（按标题，支持拼音），选中的卡片作为标签显示在输入框上方，随消息一起发送。存在用户消息的 `cards` 字段里。发给模型时写成「用户附上了这些卡片，先用 read_card 读」。旧版本会忽略这个字段。
  - 最后一条回答可以「重新回答」，最后一条消息可以修改后重发（会带上原来的卡片和上下文）。被替换的消息记在对话文档的 `dropped` 映射里（消息 id → 时间），读取时跳过；消息列表本身仍然只增不改。旧版本看不懂 `dropped`，会把新旧消息都显示出来。被替换的回答如果已经改过笔记，这些修改不会自动撤销。
  - 出错时可以直接重试（就是重新回答）。
  - **问 AI**：在卡片里选中文字，右键菜单里有「问 AI」（这个菜单替代系统菜单，所以也带复制、剪切）；手机上选中后，选区下方会出现「问 AI」按钮。选中的文字作为引用出现在输入框上方，可以补充问题再发；直接发送就是让 AI 解释。引用存在用户消息的 `context.selection` 里，发送后显示在消息上方。
  - 没有模型时，在对话面板里直接添加（选服务商 → 填 key → 测试 → 选模型），不用跳到设置。
  - 对话记录可以搜索标题，按「今天、昨天、7 天内、30 天内、更早」分组，可以重命名。
- **思考程度：** 在输入框的模型菜单里直接选（像 Claude 和 ChatGPT 的应用），不放在设置里，下一轮就生效。按服务商分别记住。是输入框里单独的一个按钮，只对支持的模型显示和发送。Anthropic 的模型以 Models API 返回的 `capabilities.effort` 为准（随模型列表一起获取）；拿不到时按模型名判断（`web/src/ai/effort.ts`）：Claude 5 系列五档全有，Opus 4.5 和 4.6 系列没有「很高」，更早的 Claude 不显示；OpenAI 兼容只对 o 系列、gpt-5、gpt-oss 显示。页面每轮把这个值传给 `ai_turn`，不支持时传空。Anthropic 用 `output_config.effort`（低到最高五档）；OpenAI 兼容用 `reasoning_effort`（低、中、高），只在选了的时候才发送，因为不是每家都认这个参数。
- **工具（只读）：** search、read_card、read_journal、get_backlinks、list_tags、find_by_tag、list_recent_cards、list_topics、topic_cards、list_tasks。用户当前看的卡片和选中的文字会随消息一起发送（输入框上方的标签可以去掉）。
- **来源：** 系统提示要求模型用 `[标题](folio:card/<id>)` 和 `[几个字](folio:block/<卡片 id>/<块 id>)` 标出来源。点击后打开卡片并定位到那个块。
- **Markdown 渲染：** 自己解析成语法树再渲染，不用 innerHTML，模型的输出不会变成页面上的标签或脚本。
- **保留回答：**
  - “存成卡片”：只保留最后一次工具调用之后的文字，链接转成卡片链接和块引用。
  - “加到今天的日记”：按粘贴的规则插入。

## 修改笔记（第二阶段）

写入工具在前端定义和执行（`web/src/ai/writes.ts`），跟 Rust 提供的只读工具一起发给模型：

| 工具 | 做什么 | 撤销 |
|---|---|---|
| create_card | 新建卡片，内容是 Markdown | 移到回收站 |
| append_to_card | 在卡片或某天日记的末尾追加；日记里按大纲粘贴的规则 | 删掉追加的块（按块 id） |
| update_block | 替换一个块的文字（只限行内 Markdown） | 恢复原来的内容；之后又被改过就不撤销 |
| rename_card | 改标题 | 改回去；之后又被改过就不撤销 |
| set_card_topic | 归入或移出已有主题 | 反过来操作 |

- **每次先问我：**
  - 模型调用写入工具后，循环暂停，对话里显示改动的预览：要写的内容、修改前后的文字、新旧标题，或是哪个主题。
  - 每处改动单独允许或拒绝，可以“全部允许”，也可以选“本次对话都允许”（只在这次运行期间有效）。
  - 拒绝或按停止时，模型会收到“用户拒绝了这处改动”，系统提示要求它不要再试，而是问用户想要什么。
  - **在卡片里审阅**（2026-11-09，`web/src/ai/review.ts`、`editor/aiReview.ts`、`ai/ReviewBar.tsx`）：
    - 对某张卡片（含日记某天）的修改、追加、改标题，同时画在那张卡片里。改动到达时自动打开卡片，跳到第一处。
    - 画法像 git diff：删掉的字红色删除线，新加的字绿色。中日韩文按字比对，其他按词（`ai/diff.ts`）；两处改动之间只隔一两个字时并成一处，免得读起来碎。
    - 三种看法：对照（同一段里标出增删）、分行（旧段在上、新段在下）、修改后（只看结果）。
    - 每处改动上方一行有接受、拒绝；卡片顶部的审阅条有上一处、下一处、全部接受、全部拒绝。
    - 对话里的预览和卡片里的是同一份提议：任一处的决定，两边同时更新。
    - 接受只是记下回答；这次回复的改动都有了回答，才按原来的顺序写入，写法、出处、撤销都和以前一样。
    - 审阅期间只用装饰显示，文档本身不变，所以不会把半决定的状态保存或同步出去。
    - 提议之后用户又改了那一段：这处标为“被你改过”，只能拒绝。写入时还会再比一次原文，不同就不写，并告诉模型重新读卡片。
- **直接修改：** 不询问，直接写入。
- **出处：** 写入的块都标为 `ai:<模型名>`（§0.3），通过编辑器写入，和打字一样。打开的编辑器会同步看到。
- **撤销：**
  - 每处改动都把“怎么撤销”和工具结果存在一起，所以以后、在其他设备上也能撤销。
  - 撤销过的记在对话文档的 `undone` 映射里；消息本身写入后不再修改。
  - 发给模型时会去掉这些记录，只发结果文字。
- **还没有的：** 删除块、移动块、修改任务状态、新建主题。删除这类会丢东西的操作要等确认的交互用顺了再加。

## 设置同步

- **存在哪：** 工作区文档的 `ai` 映射（`web/src/docs/aiConfig.ts`）。
  - `providers`：id → {name, protocol, base_url, model, models, effort, created_at, deleted_at}；
  - `models` 是用户选的模型 id，一行一个；`model` 始终写成其中第一个，旧版本只读它。旧版本只改了 `model` 时会清空 `models`，读的时候就只剩那一个模型。
  - `writes`：修改模式；
  - `keys`：id → 加密后的 key。
  - 都是可合并映射（§4.5 规则 2），两台设备同时添加的模型都会保留。
  - 旧版本不认识 `ai` 映射，会原样保留，不影响同步。
- **宿主读取：** 宿主（`src-tauri/src/ai.rs`）仍从本机设置 `ai.providers` 读模型配置。前端在工作区文档变化时，把配置镜像到这个设置里，再加上本机当前选的模型。
- **key 的加密：**
  - 由 Rust 用同步工作区密钥派生的子密钥加密：HKDF「folio secrets v1」+ XChaCha20-Poly1305，绑定工作区 id 和「ai key <模型 id>」（`folio_sync::crypto::seal_secret`）。
  - 同步本身就是端到端加密的，所以只有加入了这个同步工作区的设备能解开。页面和服务器只见到密文。
  - 没有设置同步的设备不发送 key，也解不开别人的 key，只用本机填的。
- **对账：** 打开设置、或工作区文档变化时（`reconcileKeys`）：
  - 别的设备发来新 key，或换了 key：解开存入本机钥匙串；
  - 只有本机有的 key：加密后发出；
  - 别处删掉的模型：删除本机的 key。
  - 本机记下每个 key 对应的密文（`ai.keys` 的 `synced` 字段），用来判断是否已经同步过。
- **迁移：** 以前每台设备各自配置的模型，第一次打开时合并进工作区文档，只做一次（镜像里记 `shared: true`）。
  - 接口、地址、模型都相同的，视为同一个，本机的 key 移到那个模型下（`ai_move_key`），不会出现两个「Claude」。
  - 已经删除的模型不会被加回来。

## 对话的存储（向后兼容）

旧版本的同步遇到不认识的文档类型或 id 前缀会报错，导致整个同步中断。所以对话不新增文档类型：

- 每个对话是一个 **board 类型的文档，id 是不带前缀的 UUID**。旧版本照常同步、保存，但不会显示：它们的白板列表来自工作区文档的 `boards`，Rust 只索引卡片。
- 对话列表放在工作区文档的 `chats` 映射里：`id → {title, created_at, updated_at, deleted_at}`。删除只记 `deleted_at`，所有设备都会看到。
- 消息存在根列表 `messages` 里，每条是 `{id, at, data: AiMessage 的 JSON, model?}`，写入后不再修改。读不懂的消息（来自更新的版本，或已损坏）会被跳过。
- 一定要通过 `openChat(id)` 打开对话，这样才会以 board 类型保存。
- 工作区文档的“是否有内容”以前只看 topics，现在也看 boards、templates、chats。（以前只有模板的工作区不会被保存，是一个潜在的 bug。）

## 以后：Skills

循环是自己写的 agent 循环（模型 → 工具 → 结果 → 模型），没有用框架。Skills 可以直接接进来，做法参照 Anthropic 的 Agent Skills：

- 一个 skill 是一段说明（名称、什么时候用、具体步骤），存在笔记库里（比如带特定标签的卡片），随笔记同步。
- 系统提示只列出每个 skill 的名称和一句话描述；模型觉得需要时调用 `use_skill` 工具取回完整说明，再按说明调用已有的工具。
- 这样不同服务商的模型都能用，也不需要 shell 或 Node 运行时（手机上也能跑）。
