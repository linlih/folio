# 图片与附件：本地存储 + 加密同步（设计草案，2026-10-28）

> 状态：**本地部分与同步已实现（2026-10-28）**：§3、§4、§5、§6（本机与服务器的清理）、§7 的导出。细化 ARCHITECTURE.md §4.6（文件骨架）与 §5.3 的“附件”一行。

## 0. 现状

- 编辑器里有 `image` 块（tiptap Image，块级），只能用 `/` 菜单填网址；粘贴、拖入的图片不保存。没有文件附件。
- 同步只有三种文档（卡片、白板、工作区，`folio-sync/src/client.rs` 的 `DocKind`），图片节点同步的只是网址。
- `store.db` 在迁移 1 里已建好 `assets` 表（`sha256, mime, size, original_name, created_at, meta, uploaded, local`），一直空着。
- 备份只复制 `store.db`（`VACUUM INTO`，保留 14 份）；“移动资料库”复制整个文件夹。
- 服务器请求体上限 64 MB（`folio-server` 的 `BODY_LIMIT`），只有文档日志，没有文件存储。

## 1. 目标与范围

**第一版要做到**
1. 图片：粘贴、拖入、从菜单选（手机从相册 / 文件选）进卡片，离线可看，跟卡片一起导出。
2. 文件附件：任意文件作为一个块放进卡片，显示文件名和大小，点开用系统应用打开（手机用系统预览 / 分享）。
3. 加密同步：文件在本机加密后上传，服务器看不到内容，也认不出是哪个文件；其他设备自动或按需下载。
4. **不影响文字同步的实时性**：文件走单独的通道和队列，文档更新从不等待文件上传。

**第一版不做**（留出空间，见 §8）：白板上的图片元素、PDF 阅读与批注、录音与转写、视频播放器、服务器端缩略图。

## 2. 关键决定（一览）

| # | 决定 | 理由 |
|---|---|---|
| 1 | 文件按内容寻址：SHA-256 就是文件名，不可变 | 自动去重；同步、备份、校验都简单；“改了就是另一个文件” |
| 2 | 文件放在资料库的 `assets/` 目录，不进 SQLite | 数据库和备份不膨胀；可按字节范围读 |
| 3 | **元信息写在文档节点里**（哈希、类型、大小、宽高、文件名），`assets` 表只记本机状态 | 其他设备在下载之前就能显示正确比例的占位、文件名和大小；`assets` 表不需要同步 |
| 4 | 文件同步走单独的接口，分块加密，可断点续传 | 不占文档通道；大文件不受 64 MB 请求上限影响；手机网络断了不用从头传 |
| 5 | 服务器上的文件 id = HMAC(文件 id 密钥, sha256) | 同一工作区里仍能去重，但服务器无法拿已知文件的哈希来比对“你存了这个文件” |
| 6 | 下载后用 sha256 校验内容 | 端到端完整性：服务器换掉、截断、重排都能发现 |
| 7 | 删除块不删文件；无引用满 30 天才在本机清理；服务器上没有设备再用的文件也等 30 天（可配置）再删 | 撤销、回收站、恢复备份都还找得到文件；服务器清理需要所有设备都确认，见 §6 |

## 3. 本地存储

### 3.1 目录与写入

```
<资料库>/
  store.db  index.db  backups/
  assets/
    3f/a2/3fa2…（64 位十六进制，无扩展名）
    .incoming/   写入中的临时文件
```

- **写入**：边读边算哈希，写到 `assets/.incoming/<随机名>`，`fsync` 后改名到目标位置（目标已存在就丢掉临时文件 = 去重），再在 `assets` 表插入一行，最后才把节点写进文档。崩溃时最多留下没被引用的文件，由清理处理；不会出现“文档引用了、文件却是半截”的情况。
- 启动时删除 `.incoming/` 里超过一天的临时文件。
- 单个文件上限 **100 MB**；超过时拒绝并说明。

### 3.2 `assets` 表（已存在，补一列）

| 列 | 含义 |
|---|---|
| `sha256` | 主键 |
| `mime`, `size`, `original_name`, `meta` | 首次见到时记录（`meta`：宽高等） |
| `local` | 本机是否有文件（另一台设备的文件还没下载时为 0） |
| `uploaded` | 是否已确认在服务器上 |
| `orphan_since`（**新增**，迁移 3） | 第一次发现没有任何引用的时间；重新被引用时清空 |

迁移 3 只是 `ALTER TABLE assets ADD COLUMN orphan_since INTEGER`，加列不改旧数据；照例在升级前做安全备份（`backup_before_upgrade`），升级后读回校验。

### 3.3 引用索引（`index.db`，可重建）

```sql
CREATE TABLE asset_refs (sha256 TEXT, doc_id TEXT, mime TEXT, PRIMARY KEY (sha256, doc_id));
```

索引卡片正文时收集 `image` / `file` 节点的哈希和类型（还没下载的文件按节点记的类型保存）。回收站里的卡片照常计入。以后白板有图片元素时同样计入。

### 3.4 前端读取：`folio-asset` 协议

- Rust 注册异步 URI 协议 `folio-asset`（桌面 `folio-asset://localhost/<sha256>`，Android 的 WebView 上 Tauri 映射为 `http://folio-asset.localhost/<sha256>`），前端用一个函数生成地址，**地址不写进文档**。
- 只接受 64 位十六进制、只读 `assets/` 下的文件；返回 `assets` 表里的 `mime`；支持 `Range`（以后音频、PDF 要用）。
- 本机没有这个文件时返回 404，前端显示占位（§5.4）。

### 3.5 文件怎么进来

**实际做法**：所有来源都拿到浏览器的 `File`，分块（桌面 / iOS 每块 4 MB，Android 1 MB）经 IPC 写进 Rust 的 `.incoming` 文件（`asset_begin` → `asset_write` × n → `asset_finish`）。原因：窗口关掉了 Tauri 的拖放（`dragDropEnabled: false`，白板和卡片库的拖动要用网页自己的拖放），拖入的文件只有字节没有路径；手机的系统选择框给的是 content:// 等地址，Rust 不能直接读。分块后 Android 的 JSON 传输也不会一次塞进整个文件。

| 来源 | 入口 |
|---|---|
| `/` 菜单“图片”“文件” | `<input type=file>`（手机上是相册 / 拍照 / 文件） |
| 拖入文件 | 编辑器的 drop，放在落点所在行之后 |
| 粘贴截图 / 复制的图片 | 剪贴板只有字节 |
| 粘贴网页里的远程图片 | 第一版保持网址图片，不自动下载；以后可加“保存到本地” |

- **iPhone 的 HEIC**：Windows、Android 的 WebView 显示不了，所以在 Apple 设备上导入时用系统的 ImageIO 转成 JPEG（质量 0.9，保留方向等元数据）再存，文件名改成 `.jpg`；转换失败就保留原件并记日志。其他系统收到 HEIC 时原样保存。
- 其他图片保持原图，不压缩。

## 4. 文档里的节点

**图片**（沿用现有 `image` 节点，加属性；网址图片照旧用 `src`）

```
image { asset?: sha256, src?: 网址, alt, mime, size, width, height, name, scale? }   （width / height 是像素，沿用 tiptap 图片节点的属性）
```

`scale` 是图片在卡片里显示的宽度，按所在栏宽的百分比存（10–100 的整数），没有就按图片自身大小显示（最宽到栏宽）。存百分比而不是像素，手机和电脑显示的比例才一致。桌面端拖图片右下角调整，双击这个角恢复原始大小；手机在查看大图时选“小 / 中 / 大 / 整栏 / 原始”。查看大图：桌面端双击，手机点一下（`editor/imageViewer.ts`）。

大纲里每个条目都以一行文字开头，所以在空行插入的图片排在这行空文字后面。这行空文字在光标不在它上面时不显示，圆点对着图片顶部，图片看起来就是这个条目（同 Logseq），光标移上去可以写图片说明；插入后光标到下一个新条目，像按了回车（`placeFiles`、`imageView.ts` 的 `image-line`）。存储格式不变。

**文件**（新的块级节点）

```
file { asset: sha256, name, mime, size }
```

- 显示：图片按 `width/height` 先占好位置，再加载；网页显示不了的图片格式（如 TIFF）作为文件块加入；文件显示为一行：图标、文件名、大小，点击打开。
- 打开文件：桌面把文件以原文件名复制到临时目录（文件不能被外部程序改动），用系统默认应用打开；手机用系统预览 / 分享面板。
- 块的复制粘贴、拖动、提炼成卡片都只是移动节点，文件不动。粘贴到另一个资料库时文件不在，显示占位（第一版不跨资料库复制文件）。
- 块 id、可合并容器等规则照 §4.5，不变。

## 5. 同步

### 5.1 服务器

**存储**：加密块放在数据库旁的 `<数据库文件>.blobs/<工作区>/<id 前两位>/<id>/<块序号>`，SQLite 里记文件和已收到的块（`blob_chunks`）：

```sql
CREATE TABLE blobs (workspace TEXT, id TEXT, size INTEGER, chunks INTEGER,
                    complete INTEGER, device TEXT, created_at INTEGER,
                    PRIMARY KEY (workspace, id));
```

**接口**（都带服务器令牌和设备 id，与现有接口一样校验；被移除的设备同样 410）

| 接口 | 作用 |
|---|---|
| `POST /v1/w/{ws}/blobs/have` `{ids}` | 批量问哪些已经完整存在（上传前去重、下载前确认） |
| `PUT /v1/w/{ws}/blobs/{id}/{n}` | 上传第 n 块（每块 ≤ 1 MiB 加密数据），可重复上传同一块 |
| `POST /v1/w/{ws}/blobs/{id}/done` `{chunks, size}` | 所有块到齐后标记完整，通过 WebSocket 通知其他设备 |
| `GET /v1/w/{ws}/blobs/{id}/{n}` | 下载第 n 块 |
| `PUT /v1/w/{ws}/blobs/refs` `{ids}` | 报告本设备还在用的全部文件（替换上一次的报告），返回其中服务器没有完整文件的 `{missing}`（§6） |

- 没完成的上传保留 7 天，服务器每小时清理一次。
- 服务器配置：`FOLIO_SERVER_MAX_FILE_MB`（单文件上限，默认 100）、`FOLIO_SERVER_QUOTA_MB`（每个工作区的总容量，默认不限）。超出时分别返回 413 / 507，客户端显示“文件超过服务器允许的大小”“服务器上给文件的空间用完了”。
- 一个文件传完时，服务器在实时通道上再推一次当前 head：各设备因此同步一次，正在等这个文件的设备随之重试下载（没有新增消息类型）。

### 5.2 加密

- 从工作区主密钥再派生两把密钥（HKDF，与现有派生并列）：`folio sync blob v1`（加密）、`folio sync blob id v1`（算服务器 id）。
- **服务器 id** = HMAC-SHA256(id 密钥, sha256) 取前 16 字节的十六进制，和文档标签同样做法。
- **分块**：明文按 1 MiB 切块，每块的明文是“4 字节长度 + 内容”，用 XChaCha20-Poly1305 加密，随机 nonce；附加数据 = `工作区 \n 服务器 id \n 块序号 \n 是否最后一块`，所以块不能被替换、重排，也不能被截短。
- **校验**：下载完整个文件后解密、拼接，算 sha256，与节点里的哈希一致才放进 `assets/`。
- **大小**：服务器能看到每个文件的大致大小（块数）。最后一块补齐到 64 KiB 的倍数，只露出大概大小。写进安全说明（§5.6 第 8 条）。

### 5.3 上传

- `assets` 表里 `uploaded = 0` 且本机有文件的，就在上传队列里。**开启同步时**，已有文件全部进入队列（与文档的完整历史进 outbox 一样）。
- 文件有**自己的后台线程**（`sync-files`），与文档同步分开，各自退避：文档推送照旧约 0.8 秒；每次文档同步成功后唤醒文件线程，一次一个文件，小文件优先。没有被任何卡片引用的文件不上传。
- 上传前先问 `have`：其他设备已经传过（同一文件）就直接标记 `uploaded = 1`。
- 中断后从服务器上缺的块继续传（上传前用 `have` 问一次已有哪些块）。

### 5.4 下载与占位

- 本机缺哪些文件由索引算出（`asset_refs` 里有、`assets` 里没有 `local = 1` 的），不另记一行。
- **桌面**：全部自动下载，小文件优先。
- **手机**：不在后台批量下载（Wi-Fi 下也不），用到才下：
  - 图片：打开卡片时，加载不出来的图片向后台要文件（`asset_fetch`），排在其他文件前面；
  - 文件：点开时下载；
  - 卡片菜单里有“下载本卡片的全部附件”，供出门前离线用。
  - 已下载的文件留在本机；以后再加缓存上限和“清除已下载的附件”。
- 下载不到的几种情况，图片在原位置按原比例显示一块占位并写明原因，文件块在大小后面写明：
  - 正在下载：“正在下载…”（第一版不显示百分比）；
  - 手机上还没下载的文件块：“未下载”；
  - 服务器上还没有（上传它的设备还没上线）：“文件还在另一台设备上，它上线后会自动传过来”，这个请求一直保留，每轮文件同步再问一次；
  - 校验失败或解密失败：“文件损坏，已丢弃，会重新下载”，并记日志。
- 这些状态只影响图片和文件块本身，卡片文字照常编辑和同步。

### 5.5 状态显示

设置 → 同步加一行“图片与附件”：待上传 N 个、待下载 N 个（手机上是“N 个未下载（用到时下载）”）、服务器上共多大，或最近一次失败的原因。“仅 Wi-Fi”没有做：手机本来就只下载用到的文件。

## 6. 删除与清理

**本机**
- 删掉图片 / 文件块不删文件。索引更新时，没有任何引用（含回收站）的文件记下 `orphan_since`；重新被引用（撤销、恢复、另一台设备的修改）就清空。
- 每小时随备份检查运行一次：`orphan_since` 超过 **30 天**的文件从 `assets/` 删除；同时清掉 `.incoming/` 里超过一天的残留，并把磁盘上有、表里没有的文件（崩溃在改名之后、记录之前）补记为无引用。30 天大于备份保留期（14 份每日备份），所以从备份恢复卡片版本时文件还在。
- 跨设备永久删除（§5.4，尚未实现）落地后：被永久删除的卡片立即不算引用，但仍等 30 天再删文件。

**服务器**（已实现，2026-10-28）
- 服务器不知道文件被哪些卡片引用（它看不到内容），只有客户端能判断，而且必须所有设备都同意；一台离线的设备可能刚刚引用了它。
- **报告**：每台设备把自己还在用的文件（卡片引用的，无论本机有没有；加上本机加入后还没放弃的）的服务器 id 整份报给服务器（`PUT blobs/refs`），替换它上一次的报告。集合变了就报，没变也每 6 小时报一次。
- **标记**：服务器每小时检查一次：完整的文件，没有任何未移除设备的最新报告包含它，就记下 `unused_since`；之后有设备报告用到它就清掉。
- **删除**：`unused_since` 满 30 天，**并且**每台未移除的设备在那之后都报告过（都确认不用了），才删除。从没报告过的设备（旧版本、长期离线）会让文件一直保留；在“设备”里移除它就不再算。
- **补传**：报告的返回里有服务器没有的文件；本机有的就重新排队上传，所以服务器即使删早了或丢了，只要还有设备在用，就会补回去。
- **配置**：`FOLIO_SERVER_UNUSED_FILE_DAYS`（默认 30；0 = 永不删除）。设置里显示服务器上文件的总大小。

## 7. 备份、移动、导出

- **备份**：仍只复制 `store.db`。文件不可变，加上 30 天的清理宽限期，恢复近期备份不会缺文件。`assets/` 本身的增量备份（硬链接）放到以后。
- **移动资料库**：已经复制整个文件夹（含 `assets/`），并逐个比对字节，不用改；文件多时进度要显示文件数。
- **导出 Markdown**：卡片里用到的文件复制到导出目录的 `assets/`，用原文件名（不分大小写重名时加序号），写成相对路径 `![alt](../assets/名字.png)`、`[名字.pdf](../assets/名字.pdf)`（空格、括号转成 `%20` 等）；同一个文件只复制一次；本机没有的文件只写名字。导出单张卡片时放在 .md 旁边的 `assets/`。“复制为 Markdown”和 MCP 读卡片只写文件名。
- **导出诊断信息**不含文件。
- **Logseq 导入**（以后）：其 `assets/` 里被引用的文件一起导入。

## 10. 测试

- **加密**：分块往返；改一个字节、交换两块、去掉最后一块、换到另一个文件 id 下都解不开；sha256 不符时拒绝。
- **存储**：同一文件导入两次只存一份；写到一半崩溃（模拟）不留下被引用的半截文件；清理宽限期（回收站里的卡片、撤销后重新引用、恢复备份）；迁移 3 在旧库上执行并读回。
- **服务器**：断点续传、重复上传同一块、未完成上传过期、容量与大小上限、被移除设备 410、令牌错误。
- **模拟器**（扩展 `crates/folio-sync/tests/simulator.rs`）：随机加入 / 删除图片块、设备离线、文件上传慢于文档；最后断言每台设备上被引用的文件都在且哈希一致，文档同步从未因文件而停顿。
- **界面**：WebKit 端到端（粘贴截图、拖入文件、占位到图片的切换、打开文件）；iOS 模拟器两台互传图片（相册选图、HEIC 转换、离线后补传）。
