# 统计

2026-11-22，已确认，已开发（v0.1.40）。只**读**已有数据：不改卡片文档、不改 `store.db` 结构，`index.db` 也不加表（只多一条只读查询）。界面草图：[mockups/stats-v2.html](mockups/stats-v2.html)。

## 0. 要解决什么

用了一阵子之后，人会想知道“我到底记了多少东西”：多少张卡片、写了多少字、存了多少图片、记了多久。现在只有卡片库标题旁的张数，和详情面板里一个其实是“字符数”的“字数”。

目标是**少而准**：一个小对话框，四个数字、一张热力图、一行占用空间。不做分组明细（任务有任务页，收集箱、废纸篓各有自己的页），不做排行榜、成就、目标打卡。

## 1. 参照：别人怎么做

| 应用 | 单篇 | 全库 | 放在哪 |
|---|---|---|---|
| **Obsidian** | 核心插件 Word count：当前笔记的词数、字符数（选中时数选中部分），支持中日韩 | 无内置；社区插件 Vault Statistics 在状态栏显示笔记数、附件数、文件数、链接数、词数、占用空间 | 桌面在底部状态栏，手机在右侧栏顶上 |
| **Logseq** | 无内置 | 无内置；“所有页面”列表里有反链数；字数、热力图靠插件 | — |
| **Notion** | 页面字数（只有整页，不算选区） | 无（付费版有页面浏览量分析） | 页面右上角 ⋯ 菜单最底下，灰色小字 |
| **Bear** | 字数、字符数、段落数、阅读时间、创建 / 修改时间 | 无 | 笔记右上角 ⓘ 信息面板 |
| **Craft** | 字数、字符数、阅读时间 | 无 | 文档菜单里的信息 |
| **Ulysses** | 字数、字符数、句子、段落、阅读时间；可设写作目标 | 分组（文件夹）也能看合计 | 右侧 Dashboard 面板 |
| **Typora / 思源** | 字数（中文按字、英文按词）、字符数、行数、阅读时间 | 无 | 底部状态栏，点开看详细 |
| **flomo** | 无 | **笔记数 · 标签数 · 使用天数**，加最近十几周每天写了几条的热力图；年底有年度报告 | 侧栏最上面，常驻 |
| **Day One** | 字数 | 日记篇数、写了几天、字数、照片数、连续天数、地图 | 日记本的“统计”页 |
| **Apple 备忘录** | 无 | 无 | — |

几点结论：

1. **单篇字数人人都有**，位置都很低调：信息面板、⋯ 菜单、状态栏。没有谁把它放在正文里常驻。
2. **全库统计只有“记录型”应用认真做**（flomo、Day One）：数量 + 天数 + 一张热力图。写作型（Ulysses）重目标，知识库型（Obsidian、Logseq）交给插件。
3. **中文字数是常见槽点**：按空格切词会把一整段中文算成 1 个词。Typora、思源、Obsidian 新版都改成“中文按字、英文按词”，Obsidian 社区还专门有 CJK Count 插件。
4. 热力图很受欢迎，但只在数据**本来就有**时（flomo 的每条笔记有创建时间）才便宜。没有人为了它去回放历史。

## 2. 数什么

### 2.1 字数怎么算（全 App 一个规则）

“字数” = **中日韩文字每个算 1** + **其他文字连在一起的字母数字算 1 个词**。标点、空白、emoji 不算。

- 中日韩：Unicode 的汉字（含扩展区）、平假名、片假名、谚文。
- 其他：连续的字母、数字（中间的 `'` `-` `.` 不断开：`don't`、`e-mail`、`3.14` 各算 1）。
- 例：`今天读了 Rust 2024 的书。` → 今 天 读 了（4）+ Rust（1）+ 2024（1）+ 的 书（2）= **8**。
- 只给这一个数，不另给“字符数”：两个数放一起还得解释区别。

这是 Word / WPS 的“字数”、Typora、思源的做法，中英文混排的人看到的数都对得上。

**一个规则，两份实现**：卡片详情面板在前端实时算（TypeScript，`docs/card.ts` 的 `bodyFacts`），全库统计在 Rust 算。两边共用一张测试表（同一组输入和期望值，Rust 和 vitest 各跑一遍），保证不会算出两个数。

**算哪些文字**：正文（`idx.cards.text`，每块一行，表格、代码块都在里面）。**不算**：标题（短，算不算差别不大，算了反而让“空卡片”有字数）、剪藏链接自带的网站摘要（`clip_text`，不是自己写的）、查询块（本来就没有文字）、废纸篓里的卡片。

### 2.2 全库（v2，2026-11-22 改）

第一版是四个带框的数字 + 一年的热力图：新资料库大半是灰格子，框框像后台，也只有总数。v2：

| 部分 | 内容 | 口径 |
|---|---|---|
| 标题下一句 | 从 yyyy 年 m 月 d 日开始，记录了 N 天 | 最早有记录的一天；新建过卡片或写了日记的日子数 |
| 三个总数 | 卡片 N 张 · 字数 N · 图片和附件 N | 卡片：同卡片库标题旁的数；字数：§2.1，不在废纸篓的卡片和日记；文件：不在废纸篓的卡片引用到的，去重 |
| 最近 30 天 | 新建卡片 N（↑↓ 和前 30 天比）· 写了日记 N 天 · 最长连续 N 天 | 都从 `heat` 算；资料库不满 60 天时不显示比较 |
| 日历 | 每月一个小日历，颜色越深那天新建的卡片 + 日记越多 | 可选 3 个月 / 6 个月 / 1 年，桌面默认 6、手机默认 3，选择记在本机；早于资料库的月份不画；没有“少 / 多”图例 |
| 常用主题 | 卡片最多的 5 个主题，横条 + 张数，点了打开该主题 | 前端已有的主题计数（`useTopics`） |
| 底部一行 | 资料库占用 X MB · 图片和附件 X MB | `store.db`（含 `-wal`）+ `index.db` + 本机图片附件 + `backups/` |

`library_stats` 一次给近 12 个月的 `heat`（日历最长一年，也够算前 30 天），后端不用改。

**不做**：任务数、收集箱 / 已整理 / 白板 / 废纸篓明细、标签 / 主题 / 链接 / 查询块数、段落数、字符数、未被引用的文件、空间分项，以及“每天写了多少字”的趋势（索引里只有卡片**现在**的文字，要算得回放 Loro 历史，又慢又不准）。

### 2.3 单张卡片

详情面板“信息”里的**字数**换成 §2.1 的规则；**段落**一行去掉（没人需要）。不加“字符”，不加别的行，手机也不新增“信息”面板。

## 3. 放在哪

做成和设置一样的对话框（`ShellDialog` 加 `{ kind: "stats" }`），不做成标签页：不新增标签页类型，旧版本不受影响；看完就关。桌面居中，宽约 560px；手机复用设置的全屏样式（顶栏 + 返回），四个数字两列两行，热力图只显示近半年。

**唯一入口**：卡片库标题旁原有的“N 张卡片”变成可点的（鼠标放上去提示“查看统计”），桌面和手机一样。不放侧栏，不放设置。

## 4. 怎么算

### 4.1 一条只读命令 `library_stats`

`folio-store` 加 `Store::library_stats(today, year_ago)`，`src-tauri` 加同名命令，`web/src/bindings/commands.ts` 加类型。**只读**：只有 `SELECT` 和读文件大小，不写任何表，不触发重建索引。返回：

```ts
interface LibraryStats {
  cards: number;           // 卡片库张数
  words: number;           // §2.1
  files: number;           // 图片和附件个数
  fileBytes: number;       // 它们的大小
  daysRecorded: number;    // 记录了 N 天
  firstDay: string | null; // 始于 YYYY-MM-DD
  heat: { date: string; cards: number; journal: boolean }[]; // 近一年，只含有记录的日子
  libraryBytes: number;    // 资料库占用
}
```

用到的查询（都在现有表和索引上）：

```sql
SELECT count(*) FROM idx.cards
  WHERE kind = 'note' AND deleted_at IS NULL AND inbox_at IS NULL AND archived_at IS NULL;
-- 字数：取正文，在 Rust 里按 §2.1 数（SQLite 的 length() 不分中英文）
SELECT text FROM idx.cards WHERE deleted_at IS NULL;
SELECT count(*), sum(size) FROM assets WHERE sha256 IN
  (SELECT r.sha256 FROM idx.asset_refs r JOIN idx.cards c ON c.card_id = r.doc_id WHERE c.deleted_at IS NULL);
-- 记录的日子：新建卡片的日子 ∪ 正文不空的日记那天
SELECT date(created_at / 1000, 'unixepoch', 'localtime') d, count(*) FROM idx.cards
  WHERE kind = 'note' AND deleted_at IS NULL GROUP BY d;
SELECT substr(card_id, 9) FROM idx.cards
  WHERE kind = 'journal' AND deleted_at IS NULL AND length(trim(text)) > 0;
```

**成本**：现在的资料库（约 230 张卡片、1 万字、3 个文件）不到 1 毫秒；长到 2 万张卡片、500 万字，最慢的数字数也只是几十毫秒。只在打开对话框时算一次，不缓存、不在编辑时重算。

**时区**：“今天”和“近一年起点”由前端传入，和日记、任务的“今天”一致。

**浏览器开发模式**（没有 Tauri）：内存后端 `platform/memory.ts` 按同样口径算卡片、字数和记录天数（那里没有文件，图片附件和占用为 0，占用一行不显示），方便在浏览器里看界面。

### 4.2 单张卡片

`bodyFacts`（`web/src/docs/card.ts`）的 `chars`、`blocks` 换成一个 `words`，用 §2.1 的函数（`web/src/docs/words.ts`）。不加后端。

## 5. 兼容

- 不改任何存储，不需要迁移。
- 详情面板“字数”的数字会变：纯中文卡片几乎不变（只差标点），英文多的卡片明显变小——这才是对的数。
- `ShellDialog` 是内存里的状态，不持久化，加一种不影响旧数据。

## 6. 开发顺序

1. 字数函数（Rust + TS）和共用测试表。
2. 详情面板：“字数”换新规则，去掉“段落”。
3. `library_stats` 命令 + 测试（废纸篓不算、剪藏摘要不算、日记按那一天）。
4. 统计对话框（桌面、手机）和卡片库“N 张卡片”入口，中英文文案。
5. 用真实资料库只读核对：数字和 `sqlite3 -readonly` 手算一致。
