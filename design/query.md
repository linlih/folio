# 查询块

2026-11-12，设计稿，未开发。只**新增**一种块（`query`），不改已有数据：旧版本遇到不认识的块不显示、也不删（`vendor/loro-prosemirror/tree.ts` 的 folio 补丁），升级后照常显示。界面草图：[mockups/query.html](mockups/query.html)。

## 0. 要解决什么

Folio 已经有几张“固定的查询结果”：任务页（所有任务按日期）、标签页（带某标签的卡片和块，表格 / 看板 / 段落）、反链、今天的日记列出今天到期的任务。它们覆盖了最常见的几种用法，但都是**单独的页面**，条件也是定死的。

缺的是：**在一篇笔记里放一个会自己更新的列表，条件自己定。** 典型场景：

| 场景 | 放在哪 | 条件 |
|---|---|---|
| 项目页列出这个项目还没做完的事 | 卡片「项目 A」 | 任务未完成 · 在本卡里或链接到本卡 |
| 每周回顾 | 周回顾卡片 / 日记 | 最近 7 天新建的卡片；最近 7 天的日记里带 #想法 的块 |
| 读书清单只看在读的 | 卡片「读书」 | #读书 · 状态 = 在读 · 按评分排序 |
| 某人相关的所有记录 | 卡片「张三」 | 提到 [[张三]] 的块，按日期倒序 |
| 一周内要交的东西 | 首页 / 日记模板 | 7 天内到期 · 按日期分组 |

## 1. 参照：别人做成了什么、哪里被骂

- **Logseq**：简单查询 `{{query (and [[项目A]] (task TODO DOING))}}` 好用，但要记语法；高级查询是 Datalog，绝大多数人写不出来，论坛里大量求助是“这个查询怎么写”。结果能切表格、选列。新版加了可视化的查询构建器，正是因为语法门槛太高。
- **Obsidian Dataview**：`TABLE 评分 FROM #读书 WHERE 状态 = "在读" SORT 评分 DESC`，类 SQL，比 Datalog 好懂，是下载量最高的插件之一。被骂的点：结果只读（Tasks 插件的任务能勾）；不装插件时只看到一段代码；大库下慢。
- **Obsidian Bases**（2025 进入核心）：用界面配筛选、列、排序，可以嵌入笔记。说明“界面配置 + 可嵌入”是主流方向。
- **Notion 关联数据库视图**：纯界面，筛选可以分组、嵌套“且 / 或”，普通人也会用；但只能查数据库，查不了正文里的块。

结论：
1. **默认用界面搭条件**，不要求任何语法。
2. **同时给一种能读能写的文字写法**，界面和文字是同一份条件的两种样子，改哪边另一边跟着变。
3. **不做 Datalog、不做脚本**。更复杂的需求交给 AI 生成条件（§9）。
4. **结果能直接操作**：任务能勾、日期和字段能改，点一下打开原文。
5. **只查索引，不打开文档**，大库也要快。

## 2. 三层：从一键到精细

| 层 | 给谁 | 怎么用 |
|---|---|---|
| **常用查询** | 所有人 | `/查询` 先给 6 个现成的（§2.1），选一个就出结果，之后可以再改 |
| **条件面板** | 大多数人 | 一行一个条件，每行是“什么 · 怎么比 · 值”，下拉选；全部满足 / 任一满足；每行可以取反；最多再套一层条件组 |
| **文字写法** | 想精细控制的人 | 面板里的「文字」页：`任务:未完成 在:本卡 到期:<=+7天 排序:到期`。能直接编辑，也能复制到另一个查询块 |

显示也分两层：默认按结果类型选好显示方式，想要再在「显示」页换表格 / 看板、选列、排序、分组、条数。

### 2.1 常用查询

只在新插入、还没有条件的查询块里出现。选中后直接生成条件，面板停在条件页，可以接着改。

| 名称 | 条件（文字写法） | 第一步 |
|---|---|---|
| 本卡相关的未完成任务 | `任务:未完成 (在:本卡 OR 链接:本卡) 排序:到期,优先级` | ✓ |
| 7 天内到期 | `任务:未完成 到期:<=+7天 分组:日期 排序:到期`（含已过期，标红） | ✓ |
| 最近 7 天新建的卡片 | `显示:卡片 创建:-7天.. 排序:-创建` | ✓ |
| 最近 7 天修改的卡片 | `显示:卡片 修改:-7天.. 排序:-修改` | ✓ |
| 带某个标签的卡片 | `显示:卡片 #… 排序:-修改`（先弹出标签选择） | ✓ |
| 最近日记里带某个标签的块 | `显示:块 在:日记 日期:-7天.. #… 排序:-日期`（先弹出标签选择） | ✓ |
| 本周完成的任务 | `任务:已完成 完成于:本周 分组:日期` | 第二步（要 `done_at`） |
| 某标签按字段筛选 | `显示:卡片 #读书 状态=在读 显示为:表格` | 第二步（字段条件） |

## 3. 条件

### 3.1 查什么（结果类型）

| 类型 | 一行是 | 来自 |
|---|---|---|
| 任务 | 一个任务块 | `idx.blocks`（`task_status` 不为空） |
| 块 | 一个块，连同它下面的子块（像标签页的段落视图） | `idx.blocks` |
| 卡片 | 一张卡片（不含日记） | `idx.cards` |

没选时按条件猜：有任务、优先级、截止 / 计划条件就是任务；有字段条件就是卡片；否则是块。

### 3.2 条件种类

| 条件 | 比较方式 | 值 |
|---|---|---|
| 标签 | 有 / 没有 | 一个或几个标签（几个时：都有 / 任一） |
| 任务状态 | 是 / 不是 | 未完成（待规划、待办、进行中、审核中）/ 已完成 / 已取消 / 某几个具体状态 |
| 优先级 | 至少 / 是 | 无 / 低 / 中 / 高 / 紧急 |
| 到期 / 截止 / 计划 | 在…之间 / 早于 / 晚于 / 已过期 / 没有 | 相对日期或具体日期。“到期” = 有截止看截止，否则看计划（和任务页一致） |
| 完成于 | 在…之间 | 同上（第二步，要 `done_at`） |
| 创建 / 修改 | 在…之间 | 卡片的创建 / 修改时间；块用所在卡片的 |
| 日期 | 在…之间 | 日记里的块：那天的日期 |
| 文字 | 包含 / 不包含 | 词或带引号的短语（每个词都要有，和搜索一样） |
| 位置 | 在 / 不在 | 卡片 / 日记 / 收集箱 / 本卡 / 某个主题 |
| 链接 | 链接到 / 引用 | 某张卡片 / 本卡 / 某个块 |
| 字段 | 等于 / 不等于 / 包含 / 大于 / 小于 / 为空 | 某标签数据库的字段（第二步） |

- **标签算谁的**：一个块“有”某标签，是它自己、或它上面任一层父块带着这个标签（标签单独一行、内容写在下一层是常见写法）。在卡片里（不是日记），卡片任何地方带这个标签，卡片里的块也都算有——项目卡片顶上写一个 `#项目A`，里面的任务都算。日记不这样算，否则某天写过一次 `#项目A`，那天所有任务都会被算进去。卡片类型的结果：卡片里任何地方带这个标签就算（和标签页一致）。
- **相对日期**：今天、昨天、明天、本周、上周、下周、本月、上月、最近 N 天、未来 N 天。周从哪天开始跟随地区设置（和任务日历一致，`firstDayOfWeek`）。
- **“本卡”和“本页日期”**：`本卡` 指查询块所在的卡片（或日记那天）。`本页` 日期指所在日记那一天，不在日记里就是今天。放进**日记模板**的“到期:本页”，在 11 月 3 日那页显示的就是 11 月 3 日的，翻回去看也对。`今天` 永远是真实的今天。
- **组合**：顶层“全部满足 / 任一满足”，每个条件可取反；条件组最多一层（够表达“#项目A 且（进行中 或 本周到期）”）。
- **默认排除**：回收站里的卡片；还在收集箱里的卡片（和卡片库一致，除非条件里写了 `在:收集箱`）；模板卡片（模板里的任务是占位，不该出现在任何任务列表；模板列表在 workspace 文档里，由前端随查询传过去）。

### 3.3 文字写法

**一个查询是一串用空格隔开的词。** 每个词是一个条件、一个设置或一个要搜的字。空格是“且”，`OR`（或 `或`）是“或”，括号一层。

```
任务:未完成 #项目A 到期:<=+7天 排序:到期
task:open #projectA due:<=+7d sort:due
(#工作 OR #副业) 显示:卡片 修改:本周
显示:卡片 #读书 状态=在读 评分>=4 排序:-评分 显示为:表格
```

**关键字**（中英文都认，生成时按界面语言输出）：

| 含义 | 英文 | 中文 | 值 |
|---|---|---|---|
| 标签 | `#名` `tag:` | `#名` `标签:` | 标签名；带空格的用引号 `#"读书 笔记"`；几个任一：`#a,b` |
| 任务状态 | `task:` | `任务:` | `open` 未完成 · `done` 已完成 · `canceled` 已取消 · `backlog` 待规划 · `todo` 待办 · `doing` 进行中 · `review` 审核中 · `any` 全部；几个用逗号 |
| 优先级 | `priority:` | `优先级:` | `none` 无 · `low` 低 · `medium` 中 · `high` 高 · `urgent` 紧急；可加 `>=` |
| 到期 | `due:` | `到期:` | 日期值（见下） |
| 截止 | `deadline:` | `截止:` | 日期值 |
| 计划 | `scheduled:` | `计划:` | 日期值 |
| 完成于 | `completed:` | `完成于:` | 日期值 |
| 创建 | `created:` | `创建:` | 日期值 |
| 修改 | `updated:` | `修改:` | 日期值 |
| 日记日期 | `day:` | `日期:` | 日期值 |
| 位置 | `in:` | `在:` | `cards` 卡片 · `journal` 日记 · `inbox` 收集箱 · `this` 本卡 · `topic:名` 主题:名 |
| 链接 | `links:` | `链接:` | `[[卡片标题]]` · `this` 本卡 · `((块))` |
| 结果类型 | `show:` | `显示:` | `tasks` 任务 · `blocks` 块 · `cards` 卡片 |
| 显示为 | `view:` | `显示为:` | `list` 列表 · `table` 表格 · `board` 看板 |
| 排序 | `sort:` | `排序:` | `due` 到期 · `priority` 优先级 · `created` 创建 · `updated` 修改 · `day` 日期 · `title` 标题 · 字段名；前面加 `-` 倒序；逗号分两级 |
| 分组 | `group:` | `分组:` | `card` 卡片 · `day` 日期 · `status` 状态 · 单选字段名 |
| 条数 | `limit:` | `条数:` | 数字 |
| 标题 | `title:` | `标题:` | 带引号的文字 |
| 字段 | `名=值` `名!=值` `名>=值` `名:值`（包含） `名:none` | 同左，`名:空` | 字段名和关键字重名时写 `field.名` / `字段.名` |

**日期值**：`today` 今天 · `yesterday` 昨天 · `tomorrow` 明天 · `page` 本页 · `this-week` 本周 · `last-week` 上周 · `next-week` 下周 · `this-month` 本月 · `last-month` 上月 · `+7d` / `+7天`（7 天后）· `-30d` / `-30天` · `2026-11-01` · `overdue` 已过期 · `none` 无；前面可加 `<` `<=` `>` `>=`；`a..b` 是范围，两头可省（`-7天..` = 最近 7 天）。“本周”这类本身是范围。

**其他规则**：
- 不是关键字、不是 `#` 开头的词都是要搜的字；带空格的短语用引号；前面加 `-` 是“不包含”。条件也能加 `-` 取反：`-#归档`、`-在:日记`。
- 中文输入法打出的全角符号先统一成半角：`：` `，` `（）` `“”` `‘’` `＞` `＜` `＝` `－` `＋` `。。`（→ `..`）。
- 真要搜“任务:”这几个字，加引号：`"任务:"`。
- 关键字大小写不分（`Task:` `TASK:` 都行），值里的标签名、文字原样。
- `[[标题]]` 存的是卡片 id：卡片改名后，文字写法显示新名字，查询不坏。同名卡片有好几张时，解析报“有 N 张叫这个名字的卡片”，在面板里选一张。
- 写错的地方标红并说明原因（“不认识的关键字 `到其`，是不是 `到期`？”“括号最多一层”）；没改对之前，查询块继续按上一次正确的条件显示。

**语法**（实现参考）：

```
query  := term (SP+ term)*                 // 空格 = 且；OR 优先级更低
term   := "OR" | "或" | ["-"] atom
atom   := "(" query ")"                    // 只允许一层
        | "#" name ("," name)*
        | key ":" value
        | field ("=" | "!=" | ">=" | "<=" | ">" | "<" | ":") value
        | word | "\"" chars "\""
```

`a b OR c d` 是 `(a 且 b) 或 (c 且 d)`；设置类的词（显示、排序、分组、条数、标题、显示为）不参与“且 / 或”，放在哪里都行。

## 4. 显示

| 结果类型 | 默认 | 还能选 |
|---|---|---|
| 任务 | 任务列表（复用 `TaskItem`：能勾、能改日期，点开原文），按到期日、再按优先级 | 按日期分组（像任务页）、按卡片 / 状态分组、表格 |
| 块 | 块列表，每条带出处（卡片名 / 日期），子块缩进，长的折叠（复用标签页段落视图），按日期倒序 | 按卡片 / 按日期分组 |
| 卡片 | 卡片列表（标题、摘要、修改时间），按修改时间倒序 | 表格（选列：字段、创建 / 修改时间）、看板（按单选字段分列，复用 `DatabaseViews`） |

- **排序**：最多两级；空值排最后；相同时按卡片里的顺序，保证每台设备一样。
- **条数**：默认 20 条，下面「显示全部 N 条」，点了在本次打开期间展开（不存）。上限 500，再多提示加条件。
- **能直接改的**：任务勾选、改日期；表格里的字段。改完写回原卡片（和任务页一样，`TASK_ORIGIN` 一类的提交来源，不进当前编辑器的撤销），勾掉的任务留在列表里划掉，下次重算才消失（和任务页一致，手滑可以再点一下）。
- **改文字**：点一下打开原文，滚到那个块并高亮，光标放进去（`openAt`）；桌面上 ⌘/Ctrl 点击在旁边分栏打开，查询留在原处（`toSide`）。改完回来结果自己更新。

## 5. 交互

### 5.1 查询块的样子

- 顶上一行：漏斗图标、标题、结果数，右边 ⋯ 菜单和折叠箭头。没起标题时用条件摘要，如“未完成任务 · 本卡相关 · 7 天内到期”。点标题行打开条件面板。
- 结果区左侧一条细竖线、背景比正文浅一点，和自己写的正文一眼分开。
- ⋯ 菜单：编辑条件、显示设置、复制为文字、刷新、删除。
- 编辑器里它是一个整体（像嵌入块）：上下方向键跳过它，在它前后按 Backspace / Delete 先选中、再按一次删除。可以拖动、可以缩进（作为大纲的一项）。
- 结果为空：“没有符合的任务”，下面一行灰字是条件摘要，点一下打开面板。
- 条件版本比本机高：“这个查询需要更新 Folio 才能显示”，不执行、不改写。

### 5.2 条件面板

- **插入**：斜杠菜单 `/查询`（也认 `query`、拼音 `cx`）插入查询块，面板随即打开，顶上是常用查询（§2.1）。
- **桌面**：面板是挂在查询块下方的浮层，宽 520px，不挡住查询结果（结果随条件实时更新，改着就能看到）。**手机**：从底部弹出，占屏幕约 85%，上面露出一点结果；键盘弹出时面板跟着上移。
- 面板三页：**条件 · 显示 · 文字**。改动立刻生效，没有“保存”按钮；Esc、点面板外面、或「完成」关闭。所有改动都是这个块的普通编辑，`⌘Z` 能撤回。
- **条件页**：第一行“查 [任务 ▾]，满足 [全部 ▾] 条件”。下面一行一个条件：[种类 ▾] [比较方式 ▾] [值]，右边 ⋯（取反、移到条件组、删除）。底部「+ 条件」（弹出条件种类菜单）、「+ 条件组」。
- **值的输入**：标签 → 可搜索的标签选择器（可多选）；任务状态、优先级 → 一排可多选的小按钮；日期 → 常用的几个（今天、本周、7 天内、已过期、没有日期…）加「自定义」（前 / 后 N 天、选具体日期）；文字 → 输入框；位置 → 菜单（主题再选一个）；链接 → 和 `[[` 一样的卡片搜索；字段 → 先选字段，再按字段类型给输入（单选给选项、日期给日期…）。
- **显示页**：显示为（列表 / 表格 / 看板，按结果类型给能选的）、排序（两级）、分组、条数、标题、表格的列。
- **文字页**：等宽字体的输入框，内容是当前条件的文字写法，边打边解析，错误标红并在下面说原因；对了就立刻更新条件页和结果。
- **键盘**：面板里 Tab 在各控件间移动；条件行上 ⌘⌫ 删除这一行；文字页里 ⌘↩ 关闭面板。

### 5.3 在别的地方看到查询块

| 位置 | 怎么显示 |
|---|---|
| 嵌入了带查询块的卡片 | 结果照常显示，不能打开面板；嵌入里的查询结果里再有查询，只显示标题行 |
| 白板上的卡片预览 | 只显示标题行和数量 |
| 历史版本 | 只显示标题和条件摘要（结果是现在的数据，放在旧版本里会误导） |
| 模板卡片里 | “本卡”先按模板自己算，标题行旁注明“插入后按所在卡片计算” |
| 打印 / PDF | 按屏幕上当时的结果打印 |

## 6. 存储

查询块是正文里的一个块，节点名 `query`，叶子节点（没有正文），属性：

| 属性 | 类型 | 含义 |
|---|---|---|
| `bid` | 字符串 | 块 id，和其他块一样（可以被引用、嵌入） |
| `spec` | 字符串（JSON） | 条件和显示设置，见下 |

```jsonc
{
  "v": 1,
  "title": "",                      // 空 = 用条件摘要
  "show": "tasks",                  // tasks | blocks | cards；没有 = 按条件猜
  "match": "all",                   // all | any
  "where": [
    { "k": "tag", "v": ["项目a"] },                        // 标签存小写名（和标签数据库一致）
    { "k": "task", "v": ["open"] },
    { "k": "due", "v": { "to": { "rel": "+7d" } } },        // 相对日期原样存，执行时才换算
    { "k": "group", "match": "any", "where": [
        { "k": "in", "v": "this" },
        { "k": "links", "v": { "card": "this" } }
    ] },
    { "k": "text", "v": "周报", "not": true }
  ],
  "sort": [{ "by": "due" }, { "by": "priority", "desc": true }],
  "group": "day",
  "view": { "mode": "list", "columns": [], "limit": 20, "collapsed": false }
}
```

- 整个 `spec` 存成**一个字符串属性**：两台设备同时改同一个查询时，后写的为准，不会合并出一个两边都没写过的条件。查询很少同时改，这样最简单可靠。
- 卡片、块、主题、字段、选项都存 id，不存名字：改名不会让查询失效。标签存小写名（标签没有 id），所以**标签改名、合并时也要改查询里的标签**：`renameTagIn` 顺带改每个查询块 `spec` 里的标签名（同一次提交，同样只改名字）。
- `v` 是版本号。以后加新条件种类时，旧版本遇到不认识的条件：整个查询显示“需要更新 Folio”，不执行、不改写（少一个条件跑出来的结果是错的，比不显示更糟）。不认识的字段原样保留。
- 文字写法不存，界面和文字都从 `spec` 生成、解析回 `spec`。单元测试保证：任何 spec → 文字 → spec 不变。

## 7. 执行

**分工**：前端把 `spec` 和上下文（所在卡片、所在日期、今天、周起始日、模板 id 列表）**换算成绝对条件**（相对日期变成具体日期、毫秒范围，`本卡` 变成卡片 id，单选字段的选项名变成 id），再交给后端。相对日期只在前端算一次，Rust 和网页版（内存后端）不用各写一遍。

**后端**：新命令 `query(resolved, limit) -> { rows, total }`。把条件翻成参数化的 SQL（类型化构造器，不接受原始 SQL；和 ARCHITECTURE 插件接口的 `query` 一致），只读 `index.db`，不打开任何卡片文档。

| 条件 | SQL（块 `b` join 卡片 `c`） |
|---|---|
| 标签（块、任务） | 块自己或祖先块有：递归 CTE 沿 `parent_bid` 往上，`EXISTS idx.tags WHERE card_id = b.card_id AND bid IN (祖先)`；卡片（非日记）里任何地方有：`EXISTS idx.tags WHERE card_id = b.card_id` |
| 标签（卡片） | `EXISTS idx.tags WHERE card_id = c.card_id AND tag = ?` |
| 任务状态 / 优先级 | `b.task_status IN (…)` / `b.priority IN (…)` |
| 到期 / 截止 / 计划 | `COALESCE(b.deadline, b.scheduled)` / `b.deadline` / `b.scheduled` 和 `YYYY-MM-DD` 字符串比较 |
| 创建 / 修改 | `c.created_at` / `c.updated_at` 的毫秒范围 |
| 日期 | `c.card_id BETWEEN 'journal:2026-11-01' AND 'journal:2026-11-07'` |
| 文字 | 三字以上走 `idx.fts`，短词 `LIKE`（同搜索）；卡片类型查标题和正文 |
| 位置 | `c.kind`、`c.card_id = ?`、`c.inbox_at`、`idx.card_topics` |
| 链接 | `EXISTS idx.links WHERE from_card = b.card_id AND from_bid = b.bid AND to_card = ?`；块引用查 `idx.refs`；卡片类型：卡片里任一块链接到 |
| 字段 | `json_extract(c.props, '$."' || field_id || '"')` 比较；先这样，慢了再把字段值拆成单独的表 |
| 总是 | `c.deleted_at IS NULL`、`b.type != 'query'`、不在模板 id 里、收集箱规则（§3.2） |

- **网页版**：内存后端用同一份已换算的条件在前端实现一遍；测试两边结果一致（同 `extractIndex` 对照 Rust 的做法）。
- **实时更新**：卡片变化（`CARDS_CHANGED`、同步进来的）后 300 ms 内重算**可见的**查询块（`IntersectionObserver`）；屏幕外的滚回来再算。同一条件 + 同一上下文 1 秒内的结果共用（日记流里每天的模板查询不会重复算）。
- **快**：目标 5,000 张卡片、50,000 个块时一次查询 < 20 ms（现在的搜索是 3–22 ms）。多查 1 条判断还有没有更多，总数单独 `COUNT`。
- 查询块不进全文索引，只有它的标题能搜到；结果不算反链（否则“提到本卡的块”会把自己算进去）。

### 7.1 索引要补的

| 缺口 | 影响 | 补法（都只新增） |
|---|---|---|
| 任务完成时间 | 查不了“本周完成的任务” | 勾完成时写 `done_at` 属性（块属性，旧版本忽略）；索引加一列（索引版本 +1，重建）。之前完成的没有时间，`完成于` 条件不匹配它们 |
| 块的创建时间 | 卡片里的块查不了“最近 7 天写的” | 不补。日记里的块用那天的日期；卡片里的块用卡片的创建 / 修改时间。这是大多数人想要的意思 |
| 查询块本身 | 不该被当成普通块 | 索引里 `type = 'query'`，文字为空 |

## 8. 导出、复制

- **Markdown 导出**：写成代码块，内容是文字写法（按导出时的界面语言），别的软件里也看得懂；结果是派生数据，不导出：

  ````
  ```folio-query
  任务:未完成 (在:本卡 OR 链接:本卡) 排序:到期
  ```
  ````
  `链接:[[标题]]` 用导出时的标题。以后做导入时认出这种代码块变回查询块。
- **复制为纯文本**：同上的文字写法。复制查询块再粘贴到 Folio 里，是一个查询块。

## 9. 和别的功能的关系

- **搜索**：搜索框也接受同一套文字写法（`#读书 修改:-7天..`），把现在的过滤按钮和查询统一成一种语言；搜索里「存为查询」，在当前卡片插入一个查询块。（第三步）
- **标签页 / 任务页**：保持不变，它们就是预设好的查询。实现上可以逐步改成用同一个查询引擎，但界面不动。
- **模板**：查询块可以放进模板；`本卡` 和 `本页` 在插入后的位置计算。
- **AI**：见 §9.1。
- **侧边栏**：不另做“保存的查询”。一张只放了查询块的卡片，固定到侧边栏，就是一个智能文件夹。

### 9.1 AI 创建和使用查询

需要已配置 AI（ai.md），没配置时这些入口都不出现。AI 只写**文字写法**，不写 JSON：文字写法短、好读，模型写起来准；写出来的东西一律经过同一个解析器，解析不了就不会变成查询块。

| 入口 | 怎么用 | 结果 |
|---|---|---|
| 面板里「用一句话描述」 | 在条件面板顶上输入“项目A 下周要交的东西，按日期排” | AI 返回文字写法 → 解析 → 填进条件页，结果实时出来；你看着条件和结果，满意再关面板，不满意接着改或 ⌘Z |
| AI 对话里让它加 | “在项目 A 卡片里加一个查询，列出没做完的任务” | AI 用现有写入工具（`append_to_card`、`create_card`）写 Markdown，里面放一个 `folio-query` 代码块（和导出同一种写法，§8），写入时变成查询块。走现有的审阅流程：在卡片里以“新增”显示，接受 / 拒绝 |
| AI 回答问题时自己查 | “我这周还有哪些事没做完？” | 新增只读工具 `run_query(query)`：传文字写法，返回结果行（和 `search` 一样不改任何东西）。比全文搜索更准，也能先试一下条件再写进卡片 |

- **写错了怎么办**：`run_query` 和写入时的解析报错（“不认识的关键字 `到其`”）原样返回给 AI，它改了再试；一次对话里最多重试 2 次，还不行就告诉你哪里不对，不硬写。
- **给 AI 的说明**：工具说明里附上文字写法的关键字表（§3.3，英文那列）和 3 个例子；AI 生成时用英文关键字，显示时按你的界面语言转写（`task:open` 显示成 `任务:未完成`）。
- **本卡 / 本页**：AI 往某张卡片里写的查询，`this` 指那张卡片，和手写的一样。
- **MCP**：外部 AI 工具通过同一个 `run_query` 查笔记（只读）；通过 MCP 写入时同样认 `folio-query` 代码块。
- **不让 AI 做的**：不直接改已有查询块的条件（改条件是你在面板里的事，AI 想改就新增一个、由你删旧的）。这样 AI 改坏一个你在用的查询的可能为零。

## 10. 分步做

| 步 | 内容 | 能用到的场景 |
|---|---|---|
| 1 | 查询块节点、条件面板（标签、任务状态、优先级、日期、创建 / 修改、文字、位置、链接）、条件组、三种结果的列表显示、排序、分组、条数、6 个常用查询、实时更新、`本卡` / `本页`、文字写法（中英文、全角符号）、标签改名同步、导出为代码块 | §0 表里除读书清单外的全部 |
| 2 | 字段条件、表格 / 看板显示、`done_at` 与“完成于”；**AI**：面板里一句话生成、对话里写入 `folio-query` 代码块变成查询块、`run_query` 工具（§9.1） | 读书清单这类数据库查询；回顾本周完成了什么；让 AI 帮你建查询 |
| 3 | 搜索框用同一套写法、「存为查询」、MCP 的 `run_query` | 查询和搜索合一 |

文字写法放进第一步：解析器是面板和文字页共用的核心（摘要、导出、复制都靠它），先做好它，界面只是它的一种编辑方式。每一步单独发布、单独可用。

## 11. 测试

- **单元**：spec ↔ 文字写法来回转换（中英文、全角符号、引号、取反、一层括号、错误位置和提示）；每种条件 Rust 和前端结果一致；相对日期在跨月、跨年、不同周起始日；`本卡` / `本页` 在卡片、日记、模板插入后；标签的“自己或祖先、卡片级、日记不算卡片级”规则；默认排除（回收站、收集箱、模板）。
- **兼容**：旧版本打开带查询块的文档，块不显示、编辑后保留（已有补丁，补一个测试）；新版本遇到更高 `v` 显示“需要更新”，不改写。
- **改名**：标签改名、合并后查询里的标签跟着变；卡片改名后 `[[标题]]` 显示新名字、结果不变。
- **同步**：两台设备同时改同一个查询，后写的为准、不出现混合条件。
- **性能**：5,000 张卡片、50,000 个块的库，每种条件的耗时；日记流里 30 天每天一个模板查询，滚动不卡。
- **界面**：WebKit 桌面和手机宽度：面板、勾选任务、改日期、文字页报错；安卓真机：底部面板和搜狗输入法（全角符号、选字时回车）。
