# 收集箱与标签数据库

2026-10-31。两个功能都只**新增**字段，不改已有数据：旧版本打开新数据时忽略这些字段，新版本打开旧数据时它们为空。`index.db` 是派生数据，版本号 8 → 9，升级后第一次打开时从 `store.db` 自动重建（不是数据迁移）。

## 1. 共同的存储

都放在卡片文档的 `meta` 里，和 `pinned_at`、`deleted_at` 同一层：

| 字段 | 类型 | 含义 |
|---|---|---|
| `clip_url` `clip_site` `clip_excerpt` `clip_author` | 字符串 | 收集的链接：地址、网站名、页面自己的摘要、作者 |
| `inbox_at` | 数字 | 在收集箱里（收进来的时间）；整理完删除 |
| `inbox_from` | 数字 | 收进收集箱的时间，标为「已整理」时从 `inbox_at` 留下（2026-11-01）；之后再放回收集箱又整理，仍是最早那次 |
| `props` | 可合并 map | 数据库字段的值：字段 id → 值（字符串、数字、布尔、字符串数组） |

`props` 是可合并的 map：两台设备同时填不同字段，两边都保留；同一字段后写的为准。

索引 `idx.cards` 多了 `inbox_at`、`clip`（JSON）、`clip_text`（网站、作者、摘要，供两个字的子串搜索）、`props`（JSON）。收集的卡片还有一行标题级的全文索引（网站 + 作者 + 摘要），所以按摘要也能搜到。

## 2. 收集箱

**用途**：看公众号、X、Reddit、GitHub 时遇到值得留下的内容，先存起来，之后再读、再整理。

**只存标题、摘要和链接**（用户决定，2026-10-31）：全文太大，也没必要。摘要最多 300 字。

**怎么收进来**
- **Android**：在其他 App 里点「分享」→ Folio。`folio-apk` 插件的清单给 `MainActivity` 合并了一个 `ACTION_SEND text/plain` 的 intent-filter；插件在启动（`load`）和运行中（`onNewIntent`）收下分享的文字，页面在启动和每次回到前台时用 `take_shared` 取走，存进收集箱并打开收集箱页面。
- **所有平台**：收集箱页面顶部的输入框，粘贴链接回车；输入框为空时显示「粘贴」按钮，直接读剪贴板。
- **iOS**（2026-11-01）：在其他 App 里点「分享」→ Folio。分享扩展（`src-tauri/ios-share/ShareViewController.swift`）把分享的文字和链接合成一段（文字在前，文字里没有链接时另起一行补上），写成 App Group `group.dev.folio.app` 共享目录 `shared/` 下的一个文件（文件名以毫秒时间开头，多次分享按先后取），提示“已存入 Folio 收集箱”后关闭，不联网；应用回到前台时 `take_shared` 每次取最早的一个并删掉，页面一直取到没有为止，后面和 Android 相同。`src-tauri/gen/apple` 仍不进仓库：`npx tauri ios init` 之后运行 `scripts/ios-share.sh`，它往生成的 `project.yml` 加扩展 target、两边的 App Group 权限，再跑 xcodegen；重复运行不改动。真机签名需要开发者账号的描述文件包含这个 App Group（免费的个人团队不支持 App Group）；模拟器不需要。
- 分享的文字里没有链接时，作为一条笔记收进来（第一行作标题）。

**读取标题和摘要**（`crates/folio-clip`）：在本机直接向网站请求，不经过同步服务器，内容照常加密同步。
- 普通网页：读 `<head>` 里的 Open Graph、Twitter card、`description` 和 `<title>`，最多读 2 MB，12 秒超时。
- 微信公众号文章：同上，另从页面脚本里读公众号名作作者。
- X、Reddit：网页不给程序看，改用它们的 oEmbed 接口（`publish.x.com/oembed`、`reddit.com/oembed`），拿到推文正文、帖子标题和作者。X 的长文（Article）在 oEmbed 里只有一个 t.co 链接，没有标题，这时标题用作者（"Leon Lin (@LexnLin)"）；连不上 X 时用链接里的账号（"@LexnLin"），不用 "x.com"。
- GitHub：去掉标题前的「GitHub - 」。
- 读不到（网站拦截、网络不通、浏览器模式下的跨域限制）时只存链接，分享文字里的其他字作标题，提示用户可以自己补。

**整理**：收集箱按收进来的时间倒序列出；每条可以打开卡片写笔记、打开原文、标为「已整理」（可撤销，卡片留在卡片库）或删除（进回收站）。卡片页标题下方显示来源（网站、作者、链接、摘要），在收集箱里时有「已整理」按钮。

**整理后仍看得出来源**（2026-11-01）：整理时把收进来的时间留在 `inbox_from`。卡片页标题下显示「来自收集箱 · 收于 某日」；卡片库的「全部来源 / 来自收集箱」筛选只列出这些卡片（不记住选择，和搜索一样，下次打开回到全部）。索引 `idx.cards.inbox_from`（索引版本 12，升级后重建一次）。这之前整理过的链接仍有链接字段，按卡片创建时间算作来自收集箱；这之前整理过的纯文字卡片当时没有留下记号，认不出来。

**不进卡片库**（用户决定，2026-10-31）：还在收集箱里的卡片不出现在卡片库，只是一条链接和摘要，混在手写的卡片里会很乱。标为「已整理」后才进卡片库；已经放进某个主题的也算整理过，照常显示。卡片库标题旁显示「收集箱里还有 N 条未整理」，点击打开收集箱。搜索、链接选择仍能找到它们。只是卡片库的显示规则，数据不变。

## 3. 标签数据库

**用途**：少量需要按字段整理的记录，例如读书清单（状态、评分、作者）、项目、联系人。参照 Heptabase「标签即数据库」：正文里带 `#读书` 的卡片就是「读书」这张表的行，不另建表、不另建对象。日记和回收站里的卡片不算。

**字段定义**放在 workspace 文档的 `databases` 根 map，按标签的小写名作键（改大小写不丢字段）：

```
databases: Map<tag_key, MergeableMap {
  fields: MergeableMap<field_id, MergeableMap { name, type, order, created_at, deleted_at?, options: MergeableMap<option_id, { name, color, order, deleted_at? }> }>,
  view:   MergeableMap { mode, group_by, sort_by, sort_desc },
}>
```

- 字段类型：单选（存选项 id，改选项名不用改每张卡片）、文本、数字、日期、勾选、链接。
- **删除字段只做标记**（`deleted_at`），卡片里的值不动：可以撤销，另一台设备同时填的值也不会丢。删除选项同理。
- 字段的值存在各卡片的 `meta.props`（§1），所以同步、回收站、导出都跟着卡片走。
- 视图（表格 / 看板 / 段落、分组字段、排序）随文档同步：同一个标签在每台设备上看起来一样。

**三种视图**（标签页右上角切换；没选过时，有字段的标签打开表格，还没有字段的打开段落：大部分标签只是标记，常写在日记里，而表格不含日记）
- **表格**：一行一张卡片，列为标题和各字段，单元格直接编辑（文本回车或失焦保存，单选弹出可搜索、可新建选项的菜单）。点列头排序、改名、删除（可撤销）；「+ 字段」加列。底部「新建」建一张带这个标签的卡片。
- **看板**：按一个单选字段分列，最后一列是「未设置」。桌面拖动卡片换列；触摸屏和键盘用卡片上的 ⋯ 菜单「移到」。每列底部可新建，新卡片自动填上该列的值。顶部两个按钮：分列（打开菜单选单选字段，菜单里说明只能按单选分列，所以只有一个单选字段时也看得到）和排序（字段与升降序，和表格的排序是同一个）。没有单选字段时提示「添加『状态』属性」，一步建好「待办 / 进行中 / 完成」。手机上列宽约八成屏幕，横向滑动按列对齐。
- **段落**：原来的标签页，列出所有带这个标签的块，连同每个块下面缩进的子块（保持层级，超过 8 条折叠为「显示全部」）。常见写法是标签单独占一行、想法写在下一层（Logseq、Roam 的标签页也这样显示），只列标签那一行就什么都看不到。子块里再带同一标签的，只在父块下显示一次。子块按 `idx.blocks` 的 `parent_bid` 递归查出，按 rowid（即文档顺序）排列，每块最多 200 条；MCP 的 `find_by_tag` 也带上这些子块。排序：日记按日期（回头给旧的一天补内容不会让它跑到最上面），其他卡片按最后编辑的那天，同一天里按编辑时间。

**改名与合并**（2026-10-31）：标签页标题旁的 ⋯ 菜单「重命名」（或双击标签名）、「合并到…」；新名字已被别的标签用着时就是合并，先确认。
- 所有带这个标签的文档（卡片、日记、回收站里的）逐个原地改：只改标签节点的 `name`，块 id 不变，另一台设备同时编辑同一行能合并；提交来源 `app:tag`，打开着的编辑器立即显示，某张卡片里 `Mod+Z` 不会单独撤回它。合并时一行里已经有目标标签的，删掉原标签，不留两个一样的。
- 字段：两个标签都有的同名同类型字段合成一个（目标标签的那个），卡片的值复制过去（目标字段已有值的不动），单选按选项名对应，缺的选项先加上；其余字段原样搬到新名字下（字段 id 不变，卡片的值不用改）；目标标签没有视图时沿用原来的视图。原标签的字段只标记删除，卡片里的值不动。
- 顺序：先加选项，再改文档，最后搬字段；每一步只增不删，中途关掉应用，再改一次就补完。只改大小写时字段不动。
- 另一台设备离线期间新写的旧标签不会被改，同步后旧标签页还在，再改一次即可。
- 测试：`web/test/tag-rename.test.ts`（全部文档、日记与回收站、字段合并与选项对应、视图、重复执行、只改大小写、同一行去重且块 id 不变）、`web/test/tabs.test.ts`（标签页跟到新名字、合并时并成一个）、`folio-store` 的 `renaming_a_tag_reaches_every_document_with_it`；网页预览实测改名、合并确认、带字段的 #读书 改名后看板不变；Pixel 5 上改名后 Rust 索引一致，经同步到 iOS 模拟器。

**排序**默认按创建时间正序：编辑中的行不会跳走。空值总排最后，相同时按创建时间、再按 id，保证每台设备顺序一致。

**卡片页**：标题下方按标签列出已定义的字段，可直接填写；没有字段的标签不显示（大部分标签只是随手标记，不需要数据库）。**字段属于标签，不属于卡片**：卡片页也能加字段、改名、删除，但都写明是标签的字段——「添加属性」弹窗写「会出现在 N 张带 #标签 的卡片上」，点字段名的菜单顶部写「#标签 的属性，改动对所有带它的卡片生效」；点 `#标签` 打开标签页看所有卡片（用户决定，2026-10-31，取代原先「卡片页只填值、『管理属性』跳到标签页」）。字段多时不占满屏幕：没填的字段收成「+N 个空属性」，点开再填（本次在卡片上改过的字段留在原处）；每个标签的字段组可以折叠成一行值的摘要，折叠状态按标签记在本机（`card.fieldFolds`），没记过的手机上默认折叠、桌面默认展开。仍放在标题下方而不是卡片末尾：状态、评分这类值打开就要看到，Notion、Obsidian、Capacities 也都放在顶部、靠折叠和隐藏空值控制占地。标签页工具栏的「添加属性」在表格和看板里都有，弹窗里写明「会出现在 N 张带 #标签 的卡片上」。

**索引**：`tag_cards(tag)` 从 `idx.tags` 和 `idx.cards.props` 一次查出所有行，不加载卡片文档。

**测试**：`web/test/database.test.ts`（字段顺序、选项与视图，两台设备同时加字段，空值排最后与按单选分组，带标签的卡片与它们的值）、`folio-store` 的 `a_tags_database_has_its_cards_and_their_fields`；WebKit 桌面（真实鼠标拖动看板、菜单移动、表格编辑）与 iPhone 13 尺寸（菜单移动、无横向溢出）。
